## Deferred Tool Loading for MCP Token Efficiency

**Source:** https://www.anthropic.com/engineering/advanced-tool-use
**Relevant to:** route_task, session_start
**Pattern:** Mark infrequently-used MCP tools as deferred (`defer_loading: true`). Keep a hot set of 3–5 tools in context always; defer the rest. At tool-selection time, BM25/regex search expands only the matched definitions into context. Anthropic's internal testing shows this drops upfront tool-definition overhead from ~77K tokens to ~8.7K (~85% reduction) while improving routing accuracy (e.g., 49% → 74% on MCP evals for Opus 4).
**Proposed change:** CODE_EDIT:servers/core/src/ — audit existing tool definitions; add `defer_loading` defaults to low-frequency tools; keep routing-critical tools in hot set.

## Stable System-Prompt Prefix for Prompt Cache Preservation

**Source:** https://www.anthropic.com/engineering/advanced-tool-use
**Relevant to:** session_start
**Pattern:** Deferred tools are excluded from the initial system prompt entirely, keeping the prefix stable across turns and prompt-cache-eligible. Changing the non-deferred (hot) tool set mid-session invalidates the cached prefix. The session_start skill should therefore lock its hot-tool set once at session init and never mutate it during the session.
**Proposed change:** SKILL_EDIT:session_start — add a note/guard that hot-tool selection is finalized at session init; document the cache-TTL implication (~1 hour on subscription, ~5 min on API key).

## Use-Case-Centric MCP Tool Design

**Source:** https://github.com/lirantal/awesome-mcp-best-practices
**Relevant to:** route_task
**Pattern:** Avoid mapping REST or GraphQL endpoints 1:1 to MCP tools. Each 1:1 mapping produces a fine-grained tool that forces the LLM to chain more calls and consumes more tokens per session. Instead, design tools around high-level use cases (e.g., "get_project_context" rather than separate GET /project, GET /settings, GET /members tools). This reduces total tool-call count and routing ambiguity.
**Proposed change:** CODE_EDIT:servers/core/src/ — review existing tool surface for over-decomposed endpoints; consolidate where multiple tools serve a single intent.

## Rich MCP Server Instructions for Self-Describing Tool Selection

**Source:** https://github.com/lirantal/awesome-mcp-best-practices
**Relevant to:** route_task
**Pattern:** Set a detailed `instructions` field on each MCP server (via the server's `instructions` option in the config) explaining the server's purpose, how tools map to workflows, usage constraints, and prerequisite steps. The LLM uses server instructions during tool selection; sparse or absent instructions increase routing errors and require more context from the user each turn.
**Proposed change:** CODE_EDIT:servers/core/src/ — add or expand `instructions` on each server definition; include purpose, tool→workflow mapping, and common pre-conditions.
