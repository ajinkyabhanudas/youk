## Startup Orientation Routine
**Source:** https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
**Relevant to:** session_start
**Pattern:** Each agent session opens by running `pwd`, reading the git log, and loading a progress file — a three-step orientation that lets the agent pick up exactly where the last session ended without re-deriving state from scratch.
**Proposed change:** SKILL_EDIT:session_start — add an explicit orientation block that runs `git log --oneline -5`, reads the progress/notes file, and surfaces the highest-priority unfinished item before any new work begins.

## Fix-Before-Build Health Guard
**Source:** https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
**Relevant to:** self_heal
**Pattern:** A startup smoke test checks whether the app/service is in a working state before any new feature work begins; if the check fails, the agent repairs the broken state first. Building on a broken baseline compounds debt and wastes tokens on features that sit on a cracked foundation.
**Proposed change:** SKILL_EDIT:self_heal — insert a smoke-test gate at the top: if the health check fails, enter repair mode and do not proceed to new tasks until the check passes.

## Sub-agent Response Token Cap
**Source:** https://www.anthropic.com/engineering/multi-agent-research-system
**Relevant to:** route_task, compact_context
**Pattern:** Sub-agents are instructed to condense their findings to 1,000–2,000 tokens before returning to the lead agent. The lead agent gets synthesis, not raw exploration context. This keeps the lead agent's context from ballooning as parallelism increases.
**Proposed change:** SKILL_EDIT:route_task — add an explicit return-budget instruction: "Summarise your findings in ≤2,000 tokens before returning. Do not return raw tool output or search context."

## Just-in-Time Context Loading
**Source:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
**Relevant to:** compact_context
**Pattern:** Use `head`/`tail`/narrow queries instead of loading full objects; store large intermediate results to files and read them back on demand; keep the in-context file set to the 5 most recently accessed. The lightest compaction step is clearing raw tool call results once they are deep in history.
**Proposed change:** SKILL_EDIT:compact_context — add JIT loading guidance: prefer narrow reads, cap in-context files to 5, and clear deep tool-call history before triggering full compaction.

## MCP Tool Namespace Convention (service_resource)
**Source:** https://www.anthropic.com/engineering/writing-tools-for-agents
**Relevant to:** route_task
**Pattern:** Naming tools as `<service>_<resource>_<verb>` (e.g., `github_issues_search`, `slack_messages_list`) reduces tool-selection ambiguity. Distinct tool names with no overlapping purpose cut distraction; overlapping tools cause the model to pick the wrong one.
**Proposed change:** CODE_EDIT:servers/core/src/routing.py — audit current tool names against `service_resource_verb` convention; rename any that share prefixes or overlap in stated purpose.
