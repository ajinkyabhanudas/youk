## Checkpoint-triggered Compaction (Cliff Compaction)

**Source:** https://arxiv.org/pdf/2609.26779
**Relevant to:** compact_context
**Pattern:** Compact at natural "cliff" checkpoints — completed subtask boundaries or tool-loop boundaries — rather than raw token-count thresholds. Raw-threshold compaction frequently fires mid-reasoning, cutting a decision or tool-result chain in half and losing context that was still load-bearing. Checkpoint-triggered compaction waits until a coherent unit of work finishes before summarising.

## Reusable Understanding Artifacts Persisted Across Sessions

**Source:** https://arxiv.org/pdf/2609.05510
**Relevant to:** session_start / compact_context
**Pattern:** Treat persistent agent memory as reliability infrastructure, not ephemeral state. Specific reusable artifacts — file-structure maps, API call patterns, project conventions already discovered — should be written to durable files and reread at session_start rather than re-derived from scratch each session. This keeps the working context small and makes session_start faster.
**Proposed change:** FILE_CREATE:knowledge/cross-project.md (extend with "understanding-artifacts" section) or CODE_EDIT:servers/core/src/session.py

## Tool Output Size Cap with response_format Parameter

**Source:** https://www.anthropic.com/engineering/writing-tools-for-agents
**Relevant to:** compact_context
**Pattern:** Add a `response_format` enum (concise | detailed) to every tool that can return large results. In the concise mode, drop detailed IDs and verbose fields; return only what the agent needs to decide next. One production team reported a 38% cost reduction per turn from capping tool output size with no measurable loss of task accuracy.
**Proposed change:** CODE_EDIT:servers/core/src/compaction.py

## Pre-compaction Two-Pass Tuning

**Source:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
**Relevant to:** compact_context (plugin/scripts/pre_compact.py)
**Pattern:** Structure the pre-compaction brief in two explicit passes: first maximise recall (include every architectural decision, active bug, and implementation detail, even borderline), then apply a precision cut (remove chatter, redundant tool outputs, housekeeping). youk's pre_compact.py currently builds one pass; the two-pass framing makes the trade-off explicit and auditable.
**Proposed change:** CODE_EDIT:plugin/scripts/pre_compact.py

## Session-start Smoke Test Before New Work

**Source:** https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
**Relevant to:** session_start / health.py
**Pattern:** At each session_start, run a lightweight smoke test (start the dev server, execute one E2E check) before beginning any new feature work. This surfaces bugs left by the previous session before they compound. youk's health.py runs checks but does not currently gate the session_start reply on their result; wiring a blocking smoke-test gate would prevent a new session from declaring itself ready on a broken repo state.
