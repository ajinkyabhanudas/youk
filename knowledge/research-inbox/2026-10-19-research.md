## Lazy MCP Tool Schema Loading (Tool Search)

**Source:** https://www.anthropic.com/engineering/advanced-tool-use
**Relevant to:** session_start | route_task
**Pattern:** Marking most MCP tool definitions as deferred and exposing a lightweight Tool Search tool cuts upfront context from ~55K tokens (5-server setup, 58 tools) to ~8.7K — an 85% reduction. Accuracy on MCP evals improves from 49% to 74% (Opus 4) and 79.5% to 88.1% (Opus 4.5). Keep 3-5 most-used tools always loaded; defer the rest. Implementation uses `"defer_loading": true` per tool or per `mcp_toolset`, with a regex/BM25 search tool that expands schemas on demand.
**Proposed change:** CODE_EDIT:servers/core/src/ — surface a tool-search interface over youk's MCP tool registry, deferring low-frequency tools so session_start loads only the active slice.

## Compaction Can Drop Session Constraints

**Source:** https://arxiv.org/pdf/2608.11242
**Relevant to:** compact_context
**Pattern:** A benchmark (August 2026) shows that LLM-driven context compaction regularly drops side-constraints — "always/never" rules and working agreements that were stated earlier in the session. The constraint may not appear in the compacted summary even though it was explicitly set. Invariant rules must live in AGENTS.md/CLAUDE.md (re-read each turn), not only in the running context.
**Proposed change:** SKILL_EDIT:context-sync — add an explicit pre-compaction step that writes all active contracts back to the contracts section of CLAUDE.md/AGENTS.md before summarising, so they survive the compaction boundary.

## Condensed Subagent Returns (1,000-2,000 Token Budget)

**Source:** https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
**Relevant to:** compact_context | skill:orchestrate
**Pattern:** Subagents should explore freely but return condensed summaries of ~1,000–2,000 tokens to the orchestrator, not raw exploration context. This bounds how much any one sub-task inflates the lead-agent context window.
**Proposed change:** SKILL_EDIT:orchestrate — add an explicit sub-task output budget ("return ≤2,000 tokens to caller") to any sub-task handoff instruction.

## Start-of-Session Smoke Test Before Any New Work

**Source:** https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
**Relevant to:** session_start | health.py
**Pattern:** Before starting new work each session, run a basic end-to-end check (e.g., start the server, verify the core flow responds). This catches a broken state left by the previous session before it gets deeper. A broken state discovered mid-session costs 3-5× more to untangle than one caught at the session boundary.
**Proposed change:** SKILL_EDIT:start — add a one-step "sanity smoke" at the top of session_start: run health.py (or equivalent quick check) and surface failures before loading the feature queue.
