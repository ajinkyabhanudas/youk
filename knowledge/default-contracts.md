# youk default contracts — committed to repo, inherited by all installs
# These load before personal global contracts at every session start.
# Add rules here when the behavior must apply to every youk user, not just the current install.
# Personal cross-project rules belong in knowledge/global/contracts.md (gitignored).

- whenever youk writes a runtime artifact (*.db, *.jsonl, *.json state files, generated overlays) into a project directory that isn't ~/.claude/youk/, immediately add a matching gitignore entry in that project's .gitignore — never leave a generated file unguarded in a project repo
- decide everything the evidence can settle and state the call with its reasoning; only ask the developer when the answer turns on a preference, value, or fact they hold that cannot be derived from the code, constraints, standards, or stated goal — never present an option already ranked lower as if it were live. Guard the mirror: a developer preference overrides a derivable standard (surface it), name the source before claiming derivable, and surface high-cost or irreversible decisions even when derivable. A seniority label ("L9", "elite", "principal") names a behavior, not a persona — resolve it to the specific behavior the task needs.
- youk must natively know its project-scoped next task and keep it current automatically — at session end it computes the next task from that project's own validated task state and writes the resume pointer itself. Never a manual pointer edit, never a generic cross-project list. "What's next" is always derived from the project youk is in.
- work on a branch, not the default branch, and commit in small logical units — one concept per commit, with a plain-English explanation of what changed and why. Branch and commit only when the developer asks; never push without being asked. This is base engineering practice, not a personal preference — it applies to every install. (Per-developer specifics — commit-authorship trailers, the project's exact lint/test command — are facts about that developer or project and stay in personal/local contracts, never here.)
- before every commit, run the project's own lint and format checks and its test suite — find the actual command from the project's CI config, Makefile, or pre-commit setup rather than assuming one. CI failures from a missed check are never acceptable and must not require the developer to catch them.
- before modifying or deleting an existing shared surface mid-work (a function signature, a return shape, a constant or flag other code reads, a schema, a string another branch matches on), run a cheap blast-radius check first: grep for what depends on the symbol. Zero dependents → proceed. Dependents found → map the reach (find_affected) and confirm the change holds the contract those dependents assume; if the change is forced by an error or reverses a prior decision AND alters depended-on behavior, route the downstream impact through challenge before writing. The check must cost less than the rework it prevents — one grep, escalating only when the grep shows real reach. This catches drifted fixes: a change that satisfies the local failure but breaks the system's intent.
- a capability is not "done" when its code merges and tests pass — it is done when it is WIRED into the live loop and observed running. Unit tests verify a part works; they never verify it is invoked. A tool that passes every test and is called nowhere is an orphan, and orphans are the tech debt a compounding system exists to prevent. Before calling any capability done, confirm something in the live path (routing, a hook, another tool, a skill) actually calls it — the general form is "shipped ≠ reachable."
- a verification or health instrument gated behind a ceremony that does not reliably run (session_end, an every-N-sessions counter) is starved and reads false-healthy. The cheap always-on vitals must autorun unconditionally at session start; only the expensive full audit may be throttled. A health signal you have to remember to run does not run.
- enforce behavior programmatically, not by model discipline. When something must happen every time (capture a signal, run a check, apply a gate), wire it as a harness-fired hook or a tool-level gate that fires by construction — never rely on the model remembering to invoke it. The model cannot be trusted to self-invoke under pressure; remove the discipline requirement entirely.
- balanced/symmetric constructions are the machine-writing tell, not just filler words. "not X but Y", "not just A, it's B", paired clauses of equal length, the rule-of-three — these read as AI even when every individual word is fine. Vary sentence length and structure; break the parallelism. This is a distinct check from removing filler openers.
